Overview

Enhancement One focuses on the software design and engineering category of the capstone. The artifact is the Lucid Grove Studio website component set, including reusable interface files such as backtotop.jsx, header.jsx, footer.jsx, NavDrawer.jsx, scrolltotop.jsx, and sectionstyle.jsx.

The original components were created for my business website. The enhancement converted website-specific components into reusable front-end modules that could be adapted for future projects or client builds.

React Reusable Components Prop-Driven Design Maintainability

Justification and Improvement

I selected my own website to enhance because it showcases real front-end development work, including React component design, UI structure, navigation behavior, layout organization, reusable patterns, and maintainability. The improvement was not simply copying files into another folder. The improvement was taking original components that were tied to one branded website, stripping away site-specific styling, and packaging them for reuse.

The enhanced versions were converted into reusable, prop-driven components with generic naming, flexible className support, fewer hardcoded values, and documentation for future import or reuse. This makes the components more adaptable and easier to maintain across future projects.

Technical Implementation Details

The enhanced component set was designed around reusable React patterns. The original components were useful for the Lucid Grove Studio website, but many of them were connected to specific styling, branding, or page behavior. During the enhancement, I created reusable versions that could accept values through props instead of relying on hardcoded content.

Reusable components can accept props such as children, className, title, links, visibility options, or configuration values depending on the purpose of the component. The className prop allows a future project to apply its own styling without changing the component’s internal structure. This improves separation of concerns because the component can control structure and behavior while the parent project controls appearance. 

Receive component props from the parent project
Apply default values when optional props are not provided
Merge custom className values with the component’s base structure
Render the interface structure using the provided content or children
Allow the parent project to handle styling, routing, or layout decisions

State management was kept minimal because these components are primarily structural and interface-focused. Where behavior was needed, such as navigation visibility or scroll-related interaction, the component was designed to keep that behavior isolated instead of spreading it across unrelated page files.

The reusable files were packaged separately from the live website so that the enhanced component library could be reviewed without disrupting the production site. This also created a clear before-and-after comparison between the original Lucid Grove Studio components and the enhanced reusable versions.

Course Outcomes

Outcome 2: Professional Communication

This outcome is supported through the documentation created for the reusable component library. The documentation explains the purpose of each component, how it can be imported, what props it accepts, and how another developer could apply styling or behavior in a future project.

Outcome 3: Algorithms and Computer Science Practices

Although this enhancement is mainly focused on software design and engineering, it also supports Outcome 3 through predictable rendering and reuse. Each component follows a clear rendering flow: receive props, apply optional class names or configuration values, render the correct interface structure, and allow the parent project to control styling or content.

Outcome 4: Software Engineering Tools and Techniques

This is the strongest outcome demonstrated by Enhancement One. The refactoring process demonstrates modular design, separation of concerns, prop-driven React architecture, reusable interface patterns, and maintainable front-end organization.

Outcome 5: Security Mindset

This enhancement supports a security mindset by keeping the reusable components generic and avoiding unnecessary user data handling. The components do not store sensitive information, expose customer data, or depend on private business logic.

Reflection

During this enhancement, I learned how to create reusable components in React. I quickly learned that it was not just a matter of copying code from one folder to the next. The original components worked well for my own website, but they were so closely tied to that project that I had to consider stripping what made them unique to my project.

One of the main challenges was deciding how generic the components should become. I wanted to remove the styling without removing the functionality and structure. I had to find the balance between original functionality and making each component flexible enough to adapt to future builds.

I validated the reusable components by importing them one at a time into a controlled section of the project and checking that each component rendered correctly, accepted props as expected, and allowed styling to be applied without depending on Lucid Grove Studio’s original branding.

Overall, this process strengthened my understanding of front-end software design. I learned that maintainable code is not only code that works, but code that can be adapted, reused, and understood later.
